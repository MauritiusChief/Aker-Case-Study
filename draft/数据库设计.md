# 加拿大 Aker 物业数据库

本项目数据库明确只保存单月份快照。当前数据的 As Of 为 `2026/02/25`，Month Year 为 `2026/02`。趋势分析仅作为未来扩展在应用方案中说明，不在当前 Schema 中实现多月份历史。

数据库、标准化 CSV 和后端 API 中的完整日期统一使用 `YYYY/MM/DD`；月份使用 `YYYY/MM`。前端展示层再将完整日期转换为美式 `MM/DD/YYYY`。

residential_units 表
- unit_code (PK) TEXT
- property_code (PK)(FK) TEXT: 物业的代码
- type TEXT
- area INT: in feet², 未观察到小数
- market_rent REAL
- status TEXT: OCCUPIED / VACANT / MODEL / DOWN / ADMIN
- resident_id (FK) TEXT: 可为 NULL

residents 表
- id (PK) TEXT
- name TEXT
- security_deposit REAL
- other_deposit REAL
- balance REAL: 因为付款不会区分付了 rent roll 里的哪一项，只会算有多少钱没付，所以这样设计也合理
- move_in_date TEXT: `YYYY/MM/DD`
- lease_end_date TEXT: `YYYY/MM/DD`
- move_out_date TEXT: `YYYY/MM/DD`，可为 NULL
- unit_code (FK) TEXT: 可为 NULL
- property_code (FK) TEXT: 物业的代码, 可为 NULL

rent_rolls 表：只保存当前单月份的 Charge 数据
- id (PK) INT
- month_year TEXT: `YYYY/MM`，当前只有 `2026/02`
- charge_code TEXT
- amount REAL
- resident_id (FK) TEXT

Properties 表
- code (PK) TEXT: 物业的代码
- name TEXT

Availability 不单独落表。应用根据 residential_units.status、当前 Resident 的 move_out_date，以及同一物业和单元下的 Future Resident 动态计算 occupied_no_notice、vacant_rented、vacant_unrented、notice_rented、notice_unrented、avail、model、down、admin 和相关比例。
